# BPMN Copilot 🧠➡️📊
### A Multi-Agent Process Intelligence Engine

> **Turn plain English into validated, business-ready BPMN 2.0 diagrams - then explain, audit, repair, optimize, edit by chat, export to Word/PDF/Power Automate, and work in English or German.**

BPMN Copilot converts natural-language process descriptions into correct BPMN 2.0
models using a **team of specialist AI agents** kept honest by a **deterministic
rule-based validator**. It scores process health, detects and fixes design flaws,
optimizes existing processes, lets you refine diagrams through conversation, and
exports results in the format your stakeholders need - all in a modern, bilingual,
dark "mission-control" UI.

## 🎯 The Problem & Solution

Business processes are usually documented as free text, slides, or informal diagrams
drawn without process-modelling knowledge - leading to missing start/end events,
broken flows, unclear ownership, confusing gateways, and vague task names. This slows
down reviews, audits, and automation efforts. Fixing existing processes by hand is
**expensive and requires BPMN expertise most teams don't have** - the exact pain point
identified by our Mobilithon challenge stakeholders.

**BPMN Copilot** closes that gap on both ends:
- **Create:** describe a process in plain language → get a valid, scored BPMN diagram.
- **Improve:** upload or generate an existing process → get it optimized, reviewed, and
  explained in business language - with every claim grounded in a real before/after
  comparison, never a hallucinated one.

> **Core philosophy:** AI is creative but not always correct; rules are correct but not
> creative. We combine them - agents generate and improve, a deterministic linter
> guarantees validity, and every automated claim is backed by computed evidence (a
> diff, a score, a structural check) rather than free-form LLM assertions.

## ⚙️ How It Works - The Multi-Agent Architecture

```
  Plain-language text (optionally Enhanced first)
          │
          ▼
   ┌──────────────┐     ┌───────────┐     ┌────────────────────┐
   │ Interpreter  │ ──▶ │  Modeler  │ ──▶ │ Validator (Linter) │
   │ (understand) │     │ (BPMN XML)│     │  deterministic     │
   └──────────────┘     └───────────┘     └─────────┬──────────┘
                             ▲                       │
                             │              critical issues?
                             │                       │ yes
                             │                 ┌─────▼─────┐
                             └──── feed back ──│   Fixer   │  (retry ≤ 3×)
                                               └─────┬─────┘
                                                     │ no issues
                                                     ▼
                                   ┌─────────────────────────────────┐
                                   │  Deterministic Auto-Layout       │
                                   │  (frontend, not LLM-generated)   │
                                   └─────────────────┬─────────────────┘
                                                     ▼
                          ┌──────────────┬───────────────────┬──────────────┐
                          │   Explainer  │  Automation Finder │  Optimizer   │
                          └──────────────┴───────────────────┴──────────────┘
                                                     │
                                            (Optimizer only)
                                                     ▼
                                   ┌─────────────────────────────────┐
                                   │  bpmn_diff: computed before/after │
                                   │  → grounds the rationale in FACT  │
                                   └─────────────────────────────────┘
```

1. **Interpreter** extracts actors, tasks, decisions, and events from your text.
2. **Modeler** produces BPMN 2.0 XML (semantics only - no guessed coordinates).
3. **Validator** (the *deterministic linter*, not AI) scores it and lists any critical issues.
4. If issues remain, the **Fixer** feeds them back and the Modeler regenerates -
   **repeating up to 3 times**, stopping the instant the model is clean.
5. The frontend generates a **deterministic, non-overlapping layout** for the diagram.
6. **Explainer**, **Automation Finder**, **Optimizer**, and the **Editor** (for chat)
   then work on the finished model on demand.

Every step is streamed to the UI live via Server-Sent Events, so the **pipeline
stepper** lights up and the **thought-stream log** narrates exactly what's happening -
in whichever language you've selected.

## 🤖 The Agents

| # | Agent | Role |
|---|-------|------|
| 1 | **Interpreter** | Parses the description into actors/tasks/decisions/events |
| 2 | **Modeler** | Writes valid BPMN 2.0 XML (semantics only, no guessed layout) |
| 3 | **Validator** *(rules, not AI)* | Scores health & lists issues - the source of truth |
| 4 | **Fixer** | Applies minimal changes to repair flagged issues, including reconnecting broken flows and generating proper swimlanes |
| 5 | **Editor** | Applies natural-language edit instructions; simple renames/deletes are handled deterministically without any LLM call |
| 6 | **Optimizer** | Proposes an improved version of an existing process (merges redundant steps, removes dead-ends) - every claim grounded in a computed diff |
| 7 | **Explainer** | Describes the process for a chosen business persona, or writes the Process Review Report |
| 8 | **Automation Finder** | Rates each task for RPA/Power Automate/API suitability |

> **Why a "referee"?** Correctness is *never* decided by the AI. The Validator
> (`bpmn_linter.py`) is pure, deterministic code. The Optimizer's improvement claims are
> checked against `bpmn_diff.py`'s computed diff - so the rationale you read can never
> describe a change that didn't actually happen.

## 🩺 The Deterministic Linter & Health Score

`bpmn_linter.py` parses the BPMN XML and scores it **0–100** across 5 weighted categories:

| Category | Weight | Checks |
|----------|:------:|--------|
| **Connectivity** | 30 | No dangling flows; every node reachable & wired; no dead-ends |
| **Completeness** | 25 | Exactly one start event; at least one end event |
| **Gateway Correctness** | 20 | Decision gateways named as questions (`?`); branches labelled (Yes/No) |
| **Naming Clarity** | 15 | Tasks use clear "Verb + Noun" names, not vague terms or blanks |
| **Ownership / Lanes** | 10 | Swimlanes/pools present so task ownership is explicit |

**Bands:** Audit-Ready (90–100) · Solid (70–89) · Needs Work (50–69) · At Risk (<50).

Additional structural checks (added as part of hardening) catch **duplicate element
IDs**, **broken swimlane references**, and **elements missing from the diagram** -
these only ever fire on genuinely broken models, so a clean model's score is never
affected.

## 🧩 Core Concepts & Robustness Engineering

**Multi-Agent Orchestration (custom, framework-free).**
Hand-written Python talking directly to each provider's REST API - no AutoGen /
LangChain / LangGraph dependency. Lightweight, transparent, and provider-agnostic.

**Deterministic Validation (the referee pattern).**
A rule-based validator owns correctness. The AI proposes; the rules dispose.

**Grounded, Non-Hallucinating Explanations.**
The Explainer is fed a structured node/flow summary and told to narrate only what
exists. The Optimizer's improvement rationale is generated from a **computed diff**
(`bpmn_diff.py`), not free-form claims - verified to never describe an unmade change.

**Deterministic Editing for Simple Operations.**
Renames and deletes are parsed and applied directly on the XML tree - no LLM
round-trip, instant, with element IDs preserved programmatically. Ambiguous targets
(multiple matching nodes) are detected and surfaced to the user instead of guessed.
Complex instructions still fall back to the LLM Editor agent.

**Deterministic, Idempotent Packaging (Power Automate).**
The exporter builds a real Dataverse Solution `.zip` using UUIDv5 for stable,
three-way-consistent GUIDs and forward-slash zip paths - rebuilds are reproducible and
imports don't hit path-separator issues.

**Self-Correction & Graceful Degradation Everywhere.**
Every agent call that produces XML retries on parse failure (bounded, with
truncation-aware feedback). On total failure, the system **never crashes** - it
returns the original model plus a clear warning. Input size limits and safe XML
parsing (blocking XXE/billion-laughs patterns) protect the backend from malformed or
oversized input.

**Provider-Agnostic AI Client.**
One `chat()` interface normalizes every provider to the right wire protocol
(OpenAI-compatible, Anthropic Messages, Gemini generateContent, Azure OpenAI via
Managed Identity), including a **mock** provider for zero-key demos.

**Deterministic Document Export.**
PDF/Word/Markdown report rendering has zero AI dependency - it formats the exact JSON
already shown on screen, so exports never fail due to AI provider issues and always
match what the user saw.

**Accessibility-First, Bilingual, Themable UI.**
Semantic color tokens, ≥4.5:1 contrast, visible focus rings, 44px touch targets,
keyboard support, reduced-motion handling, and a bpmn-js canvas themed correctly for
dark mode - plus full English/German localization of the entire UI chrome.

## 🌐 Internationalization (English / German)

A toggle in the header (**EN / DE**) switches the **entire UI** instantly - every tab,
button, placeholder, tooltip, and message across Compose, History, Examples, the BPMN
canvas, all 5 Process Intelligence tabs (Health/Issues/Explainer/RPA/Optimize), the
chat panel, Settings, and the thought-stream log. The choice persists across sessions.

Beyond the UI chrome, selecting German also instructs every agent to **produce its
generated content in German** - task/gateway names, Explainer narratives, Optimizer
rationale, and Process Review Reports. Element IDs and BPMN XML tags always remain in
English, as required for valid BPMN 2.0.

This was built specifically to support German-speaking stakeholders reviewing and
using the tool in their native language.

## 🚀 Getting Started

> Recommended: **Python 3.**** and **Node 18+**.

### Backend (terminal 1)
```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1         
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env           
python -m uvicorn app.main:app --reload --port 8000
```

### Frontend (terminal 2)
```powershell
cd frontend
npm install
npm run dev
```

Open **http://localhost:5173**. It boots in **Demo mode** (no API key), so you can try
the whole flow immediately. Click the provider button (top-right) to add your own key,
or use the **EN/DE** toggle right away - the UI works in both languages even in demo mode.

> **Windows shortcut:** double-click `run-dev.bat` to start both servers.

### Production (single process)
```powershell
cd frontend; npm install; npm run build
cd ..\backend; python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```
FastAPI then serves the built UI at **http://localhost:8000**.

## 🔧 Configuration & AI Providers

Set the provider/key in the **Settings** dialog (stored only in your browser and sent as
per-request headers), or as server defaults in `backend/.env`:

| Provider | `AI_PROVIDER` | Example model |
|----------|---------------|---------------|
| OpenAI | `openai` | `gpt-4o` |
| Anthropic (Claude) | `anthropic` | `claude-3-5-haiku` |
| Google Gemini | `gemini` | `gemini-2.5-flash` |
| xAI Grok | `xai` | `grok-4` |
| Groq / Mistral / OpenRouter / DeepSeek / Together | *(name)* | *(their model id)* |
| Ollama (local, no key) | `ollama` | `llama3.1` |
| **Azure OpenAI (Managed Identity)** | `azure` | your deployment name |
| Custom OpenAI-compatible | `custom` (+ `AI_BASE_URL`) | your model |
| **Demo (no key)** | `mock` | `mock` |

**Azure Managed Identity setup:** enable a Managed Identity on the host running the
backend, grant it the **"Cognitive Services OpenAI User"** role on your Azure OpenAI
resource, then select `azure` as the provider - the Base URL field takes your Azure
endpoint and the Model field takes your deployment name. No API key is ever needed or
stored. Locally, `DefaultAzureCredential` falls back to your `az login` identity.

**Corporate network / SSL:** if a real provider call fails with `CERTIFICATE_VERIFY_FAILED`,
run once: `pip install pip-system-certs` (trusts the Windows cert store), or set
`REQUESTS_CA_BUNDLE` to your root CA `.pem`. Demo mode makes no external calls.

**Note on free tiers:** free Gemini/others have low per-minute limits (HTTP 429). Space
out AI actions by ~30–60s, or use Demo mode for rapid testing.

## 🧪 Testing

The project has been extensively unit-tested throughout development:
- **Linter** (structural checks, duplicate IDs, missing DI): verified against clean and
  deliberately broken models, confirming zero score impact on well-formed diagrams.
- **Deterministic edit engine** (`bpmn_edit.py`): rename/delete with ID preservation,
  ambiguity detection, safe fallback to the LLM Editor - covered by an automated
  `pytest` suite (`test_editing.py`).
